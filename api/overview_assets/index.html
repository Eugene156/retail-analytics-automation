    Testing and evaluation
    Historical local result: 56 selected CI tests passed on 11 October 2026, as recorded in PROJECT.md (P5-D). This is a saved result, not a fresh run or a coverage percentage.
    • Recovery policy and workflow helper contracts
    • Publication security and secret-exclusion checks
    • Offline AI tool-selection, factual, citation and schema checks
    • OpenAPI/Postman artifact validation
    • Structured logging and correlation
    AI Evaluation report: eight historical P2/P3/P4 cases replayed offline. These bounded checks are not a general model-accuracy benchmark. Live LLM workflows run separately and are excluded from portable CI.
    Configured pytest modules
    

    GitHub Actions: configured, hosted run unverified
    Portable checks run on push, pull request and manual dispatch. Ubuntu runner, Python 3.12, five-minute timeout, read-only repository permission, and checkout without persisted credentials.
    1. Checkout source and set up Python
    2. Install pinned lightweight CI requirements
    3. Run publication/static checks
    4. Run six selected pytest modules without Docker, databases, credentials or local LLMs
    This is CI configuration. No automated deployment/CD pipeline or successful GitHub-hosted run is claimed.
    Actual .github/workflows/ci.yml
    Pinned CI requirements
    

    Request validation, security and observability
    • CalculationRequest validates source identity, explicit time offsets, historical boundaries and a 31-day window.
    • API bearer authorization is checked before body parsing; owner review uses separate authority.
    • The local owner portal enforces Host/Origin, session and CSRF protections. Creation is separate from approval/publication.
    • Report drafts use idempotency keys; approvals bind report/request hashes and the exact target/version/deadline.
    • Main/P2 HTTP middleware generates a server-owned X-Request-ID and JSON completion event; caller correlation values are not echoed.
    Safe completion event contract
    timestamp · event · service · http_request_id · method · route
status_code · response_started · duration_ms · outcome
    Source: api/observability.py. Only allowlisted route templates are logged; payloads, raw URLs, headers and credentials are excluded. This is HTTP correlation, not distributed tracing. n8n execution IDs separately identify workflow history.
    Read-only local HTTP example (not executed here)
    curl -i http://127.0.0.1:18090/healthz
    Observe X-Request-ID in the response. No private logs are embedded in this page.
    

    Reviewed developer artifacts
    Download public documentation locally below. These are existing repository artifacts, not new API routes.
    OpenAPI: reviewed eight-path projection. Runtime /openapi.json requires API authorization; Swagger /docs and ReDoc /redoc are intentionally disabled.
    Postman: ten requests (seven GET, three POST). Keep api_token private; the provided environment contains a blank secret. Run safe smoke/read scenarios first. The state-changing draft request is explicitly gated and requires separate authorization; it never approves or publishes.
    Postman GUI/Runner and Swagger viewer import remain manual checks. This page does not install or launch either tool.
